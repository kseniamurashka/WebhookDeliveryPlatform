# Архитектура

## Компоненты

- **FastAPI** принимает команды управления проектами, endpoint, подписками и событиями.
- **PostgreSQL** хранит конфигурацию, события, доставки и неизменяемую историю попыток.
- **Redis** выступает брокером и result backend для Celery.
- **Celery worker** выполняет HTTP-доставку вне жизненного цикла API-запроса.

## Поток события

1. API проверяет проект и `Idempotency-Key`.
2. По точному типу события и подписке `*` выбираются активные endpoint.
3. Событие и все доставки фиксируются одной транзакцией.
4. Идентификаторы доставок отправляются в Redis.
5. Worker блокирует запись доставки, защищаясь от параллельной отправки.
6. Тело сериализуется детерминированно и подписывается HMAC-SHA256.
7. Результат HTTP-запроса сохраняется как `DeliveryAttempt`.
8. Временная ошибка повторяется с exponential backoff и jitter; постоянная ошибка переводит доставку в `dead`.

## Границы надёжности

Сервис реализует модель доставки **at least once**. Получателю следует дедуплицировать сообщения по `X-Webhook-Id` либо `X-Webhook-Delivery`. `Idempotency-Key` предотвращает повторное создание одного события при повторе клиентского API-запроса.

Секрет endpoint возвращается только при его создании и явной ротации. Во всех обычных ответах API секрет скрыт.
